# Investigation Notes – Linux Package Installation Investigation

## 1. Investigation Summary

The objective was to examine Linux package-management activity and determine how DNF and RPM operations could be monitored through Auditd and collected by Wazuh.

The investigation was performed on a Rocky Linux 9.8 virtual machine. It included package inventory checks, DNF history review, RPM metadata validation, Auditd execution monitoring, and Wazuh alert inspection.

The exercise did not establish a successful new package installation. The selected package, `tree`, was already present on the system.

## 2. Host and Package-Manager Identification

The operating system was identified as:

- Rocky Linux 9.8 (Blue Onyx)
- Kernel: `5.14.0-687.31.1.el9_8.x86_64`
- Architecture: x86-64
- Virtualization: VMware

Package-management versions:

- DNF: 4.14.0
- RPM: 4.16.1.3

Commands used:

```bash
cat /etc/os-release
uname -r
hostnamectl
dnf --version
rpm --version
```

## 3. Package Inventory Review

The installed package inventory was collected using:

```bash
rpm -qa
rpm -qa --last | head -30
```

This provided a baseline of installed packages and their recorded installation times.

The inventory was useful for understanding the existing system state before attempting a package installation.

## 4. DNF Transaction History

DNF history was reviewed using:

```bash
dnf history
```

The available history contained previous package-management transactions, including Wazuh component installations from August 1, 2026.

Transaction ID 29 was examined:

```bash
dnf history info 29
```

The output showed:

- Command: `install wazuh-dashboard-4.13.1-* -y`
- Return code: Success
- Package altered: `wazuh-dashboard-4.13.1-1.x86_64`
- Transaction date: August 1, 2026

This was a historical transaction from the existing environment. It was not generated by the Lab 133 exercise.

## 5. DNF Log Review

The DNF log was inspected:

```bash
ls -lh /var/log/dnf.log
tail -50 /var/log/dnf.log
```

The log contained repository metadata activity on November 10, 2026, including metadata refresh and repository access.

The observed metadata activity should not be interpreted as proof of a package installation.

## 6. Auditd Service Validation

Auditd status was checked:

```bash
systemctl status auditd --no-pager
auditctl -s
auditctl -l
```

Observed state:

- Auditd service: active (running)
- Audit enabled: 1
- Lost events: 0
- Initial audit rules: No rules

The initial absence of audit rules provided a clean starting point for the temporary Lab 133 monitoring rules.

## 7. Package-Manager Executable Identification

Executable paths were checked:

```bash
command -v dnf
command -v rpm

readlink -f "$(command -v dnf)"
readlink -f "$(command -v rpm)"
```

Observed paths:

| Command | Executable path | Resolved path |
|---|---|---|
| DNF | `/usr/bin/dnf` | `/usr/bin/dnf-3` |
| RPM | `/usr/bin/rpm` | `/usr/bin/rpm` |

The resolved DNF path is relevant when interpreting executable-watch coverage.

## 8. Auditd Execution Monitoring

Temporary execution watches were added:

```bash
auditctl -w /usr/bin/dnf -p x -k lab133_package_mgmt
auditctl -w /usr/bin/rpm -p x -k lab133_package_mgmt
```

Auditd displayed the warning:

```text
Old style watch rules are slower
```

The rules were nevertheless listed by:

```bash
auditctl -l
```

The configured permission was `x`, which monitors execution of the watched paths.

## 9. Existing Package Validation

The package `tree` was checked:

```bash
rpm -q tree
```

Observed result:

```text
tree-1.8.0-10.el9.x86_64
```

Additional package checks were performed:

```bash
rpm -qi tree
rpm -ql tree
rpm -qf /usr/bin/tree
tree --version
```

These checks confirmed the package metadata, installed files, file ownership, and executable version.

The package was already installed before the DNF installation attempt.

## 10. DNF Installation Attempt

The following command was executed:

```bash
dnf install tree -y
```

DNF returned:

```text
Package tree-1.8.0-10.el9.x86_64 is already installed.
Dependencies resolved.
Nothing to do.
Complete!
```

This was a no-op installation request. No new installation transaction was established by this command.

The absence of a new package installation is an important finding, not a failed investigation.

## 11. Audit Event Analysis

Audit events were reviewed with:

```bash
ausearch -k lab133_package_mgmt -i
```

The records included:

- Audit rule addition events.
- RPM executable activity.
- RPM query arguments such as `rpm -q tree`, `rpm -ql tree`, and `rpm -qf /usr/bin/tree`.

The RPM execution records showed successful `execve` activity.

For example, the recorded command arguments included:

```text
argc=3 a0="rpm" a1="-q" a2="tree"
```

These events establish that RPM was invoked to query package information.

They do not establish that RPM installed, upgraded, or removed a package.

## 12. Wazuh Collection Validation

The Wazuh configuration was inspected:

```bash
grep -n -A 8 -B 3 "/var/log/audit/audit.log" /var/ossec/etc/ossec.conf
```

The configuration contained:

```xml
<localfile>
  <log_format>audit</log_format>
  <location>/var/log/audit/audit.log</location>
</localfile>
```

The Wazuh manager was active, and the log collector process was present.

Commands used:

```bash
systemctl status wazuh-manager --no-pager
pgrep -af wazuh-logcollector
```

## 13. Wazuh Alert Analysis

A Wazuh alert was observed in Discover.

Relevant fields:

| Field | Value |
|---|---|
| Rule ID | 80705 |
| Rule Description | Auditd: Configuration changed. |
| Rule Level | 3 |
| Rule Groups | audit, audit_configuration |
| Audit Type | CONFIG_CHANGE |
| Audit ID | 221 |
| Audit Key | null |
| Location | `/var/log/audit/audit.log` |
| Agent ID | 000 |
| Timestamp | Nov 10, 2026 @ 08:53:09.152 |

The raw event contained:

```text
type=CONFIG_CHANGE
op=add_rule
key="lab133_package_mgmt"
list=4
res=1
```

This event represented the addition of the RPM execution watch rule.

The `data.audit.key` field was null in the displayed Wazuh document, but the raw `full_log` contained the key in the configuration-change record.

The alert therefore confirmed Wazuh processing of an Auditd configuration-change event. It was not a package-installation alert.

## 14. Audit Rule Cleanup

The first cleanup attempt was:

```bash
auditctl -W /usr/bin/dnf -k lab133_package_mgmt
auditctl -W /usr/bin/rpm -k lab133_package_mgmt
```

Both attempts returned deletion errors because the deletion arguments did not match the installed watch rules.

The exact rule syntax was then used.

DNF rule removal:

```bash
auditctl -W /usr/bin/dnf -p x -k lab133_package_mgmt
```

The subsequent check showed that only the RPM rule remained.

RPM rule removal:

```bash
auditctl -W /usr/bin/rpm -p x -k lab133_package_mgmt
```

Final verification:

```bash
auditctl -l | grep -E 'lab133_package_mgmt'
```

The final command returned no matching output.

This confirmed removal of both temporary Lab 133 rules.

## 15. Final Assessment

### Confirmed

- Rocky Linux 9.8 was the investigation host.
- DNF and RPM were available.
- Auditd was active.
- The `tree` package was already installed.
- DNF returned `Nothing to do` for the `tree` installation request.
- RPM query execution was recorded by Auditd.
- Wazuh collected an Auditd configuration-change event.
- Wazuh rule 80705 processed the rule-addition event.
- Both temporary Lab 133 audit rules were removed.

### Not Confirmed

- A new package installation during the exercise.
- A package upgrade or removal during the exercise.
- A Wazuh alert specifically identifying a successful package installation.
- A complete end-to-end DNF installation detection workflow.

## 16. Investigation Conclusion

The exercise demonstrated the value of correlating package inventory, DNF history, RPM metadata, Auditd records, and Wazuh alerts.

The observed telemetry confirmed RPM query execution and Auditd configuration-change collection. It did not confirm a new package installation.

A package installation investigation should rely on transaction results and package-state changes, not merely on the execution of a package-management command.
